# YetAnotherTown

基于 Fabric 的 Minecraft 小镇协作模组：在游戏内登记工程、领取任务、认捐材料、留下空间留言并维护公共设施。

## 架构

- 客户端模组提供主页、协作平台、管理页面，连接独立小镇服务。
- 一个模组 JAR 包含 Minecraft **26.3、26.2、26.1.2** 的独立适配层。每个游戏版本安装对应版本的 Fabric API、Xaero's World Map、Xaero's Minimap。
- Xaero 底图保留在玩家本地；服务同步区块区域和小镇资料，不汇集成员的地形数据。
- 外置服务仅使用 Node.js 标准库，以原子写入 JSON 保存数据。客户端读取当前游戏玩家实体的 UUID 和名字，小镇权限独立于游戏 OP。
- 领域术语见 [CONTEXT.md](CONTEXT.md)。

构建验证使用的前置版本如下；依赖下载地址和校验值固定在 `compat/dependencies.lock.json`。

| Minecraft | Fabric Loader | Fabric API | World Map | Minimap |
| --- | --- | --- | --- | --- |
| 26.3 | 0.19.5 | 0.163.0+26.3 | 1.47.0 | 26.6.0 |
| 26.2 | 0.19.5 | 0.161.0+26.2 | 1.47.0 | 26.6.0 |
| 26.1.2 | 0.19.5 | 0.155.3+26.1.2 | 1.47.0 | 26.6.0 |

## 使用与配置

需要 Node.js 24+、JDK 25+。不需要安装 npm 依赖，也不需要浏览器后台。

```powershell
cd server
node src/server.mjs
```

本地服务默认监听 `127.0.0.1:37841`。需要修改时将 `server/config.example.json` 复制为 `server/config.json`；默认数据文件为 `server/data/town.json`。

安装客户端 JAR 和三个前置模组后，按 **K** 打开小镇界面，按 **H** 展开附近说明。进入世界后自动使用当前游戏 UUID 连接，无需额外验证。连接后可创建小镇或输入八位数字 ID 加入。小镇密码可由有权限的管理设置或关闭；新加入者始终为只读新人，经过审核分配权限组后参与协作。玩家可加入多个小镇并切换当前小镇。

原版“选项 → 控制 → 按键绑定 → YetAnotherTown”可以修改、清空或重置两个按键，修改随游戏 `options.txt` 保存。默认键使用各版本原版常量，兼容 26.3 的 SDL 扫描码；首次升级会修复旧版误保存的 PageUp／Pause 默认绑定，其他自定义重绑保留。旧配置中的数字 `openKey`／`nearbyKey` 自动迁移，不再覆盖原版设置。

可选安装对应版本的 [ModMenu](https://modrinth.com/mod/modmenu)：26.3 用 21.0.0、26.2 用 20.0.3、26.1.2 用 18.0.2。在模组列表选择 YetAnotherTown 并打开配置，可修改服务地址、提示距离、刷新间隔和动画，并跳转原版按键设置。小镇主页的“连接设置”也可打开同一页面，不需要 ModMenu。

客户端在 Fabric 的 `CLIENT_STARTED` 事件中初始化界面和头像，等待游戏完成 GUI、选项及皮肤管理器的构造，避免启动入口阶段的空指针崩溃。

客户端首次启动生成 `config/yetanothertown.json`：

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `endpoint` | `http://127.0.0.1:37841` | 服务根地址；远程连接使用 HTTPS |
| `nearbyRadius` | `48` | 附近信息提示的最大距离，单位为方块 |
| `pollIntervalSeconds` | `10` | 当前小镇资料刷新间隔 |
| `animationEnabled` | `true` | 界面装饰动效开关 |
| `mapBindings` | `{}` | 每个服务、小镇、周目和维度对应的个人 Xaero 地图实例；通过游戏内绑定按钮维护 |

配置会校验字段和取值；会话令牌只保留在客户端内存。

Logo 默认使用 Minecraft 物品 ID，例如 `minecraft:oak_sapling`；也支持资源包贴图 `texture:命名空间:路径.png`。自定义贴图需由成员安装相应资源包。

### 协作功能

| 功能 | 操作与结果 |
| --- | --- |
| 建设预约 | 打开 Xaero 小镇地图，按住 Shift＋左键拖动框选区块矩形，确认后填写工程名称、建筑／机器／其他、用途、负责人、预计时间和备注；管理审批，地图显示工程状态 |
| 空间留言 | 记录位置及可见范围；附近出现简短提示，按键展开，平台可随时查阅；项目组留言由服务端限制可见性 |
| 工程任务 | 工程拆分为任务，成员领取、提交，负责人确认 |
| 材料认捐 | 展示所需、认领和已确认数量；成员认领份额，交付后由负责人确认 |
| 公共设施 | 维护操作说明、使用规则、维护人与坐标；靠近时提示 |
| 维修工单 | 报告时带入当前世界、维度和坐标，管理按待处理、处理中、已解决流转 |

小镇管理可以创建自定义权限组，逐项配置发布、领取、审批和管理能力，再为成员分配。新人权限固定只读；镇长唯一，通过移交变更。工程负责人管理自己负责的工程，不能因此获得全镇管理权限。

工程采用“待审批 → 施工中 → 待验收 → 已完成”的流程。区块重叠仅提示冲突，由管理决定是否批准。认捐和验收均为人工记录；导航提供目标路标、方向、距离和维度提示。

任务可在确认前释放，认捐可在确认前取消。工程任务和材料交付全部确认后，负责人再提交工程验收。

### 世界与历史

服务器地址、周目世界和维度分别记录。同一地址可以登记多个世界或周目。换周目时新建世界记录，归档旧记录；历史周目只读，保留工程、任务和留言。

每位成员在“管理 → 世界与周目 → 世界详情”将当前维度的个人 Xaero 地图绑定到指定周目；主世界、下界、末地分别绑定。这个操作只保存个人配置，新人和历史记录也可使用，不修改全镇资料。错误绑定可解除后重设。

换周目前保留旧 Xaero 实例，新周目使用独立实例；同镇同维度禁止多个周目共用同一个个人底图。历史查看使用保存的实例并暂停该界面的地图写入，缺少对应底图时明确提示。请同时保留 `config/yetanothertown.json` 和个人 Xaero 地图目录，避免只有业务记录而丢失地形。

## 验证

```powershell
npm run check
npm test
npm run build
```

构建工具下载并核验 Minecraft、Fabric、Xaero 和可选 ModMenu 官方依赖，按固定版本分别编译适配层，再合并为 `build/libs/yetanothertown-1.1.0.jar`。验证包含服务业务与 HTTP 接口测试、客户端配置和地图绑定测试、三个版本的真实原版按键分发回归，以及静态引用和反射接口检查。仅验证客户端改动可运行 `npm run test:client`。

自动化验证不启动 Minecraft，不包含实际游戏画面、输入交互或真实账号登录联调的验证。

## 部署

首版以本地服务验证为目标。单个数据文件只运行一个服务进程。对外部署时将 Node 服务放在 HTTPS 反向代理后，服务端口只对可信网络开放。完整备份服务数据目录及玩家本地 Xaero 地图目录；归档业务记录不会自动备份地形。

## 安全边界

- 服务信任客户端提供的游戏 UUID，不验证其真实性；修改过的客户端可冒用其他 UUID。因此适用于信任成员的小镇协作环境，不能作为公开服务的防冒用认证。不会发送启动器访问令牌或进行 Mojang 会话验证。
- 每次写入均在服务端检查权限、工程状态、周目归档状态和关联关系。
- 小镇加入密码使用带盐哈希保存。项目组留言对无权限的成员不返回。
- 本工具提供登记与协作，不执行地块保护、物品扣除、机器控制、传送或自动寻路。
- Xaero 前置由玩家从[官方 World Map 页面](https://modrinth.com/mod/xaeros-world-map)和[官方 Minimap 页面](https://modrinth.com/mod/xaeros-minimap)安装，发行包不内置其程序。
