# Yet Another Town

基于 Fabric 的 Minecraft 小镇协作模组：在游戏内预留建设区域、登记工程、查看工程范围并提交维护工单。

当前开发代号为 **v1.0.0alpha16**（简称 **v1.0.0a16**）。正式发布必须获得用户明确授权；此前只递增 alpha 序号，不使用正式发布版号或创建正式发布。Fabric 与 npm 元数据使用标准预发布格式 `1.0.0-alpha.16`，JAR 文件使用 `1.0.0alpha16`。

## 架构

- 客户端模组通过窗体内顶部横排的“主页 / 平台 / 管理”菜单连接独立小镇服务。资料自动同步，不提供手动刷新按钮或通用保存成功提示；错误仍可在状态区查看。每个小镇页面的标题均带房子图标。
- 一个模组 JAR 包含 Minecraft **26.3、26.2、26.1.2** 的独立适配层。每个游戏版本安装对应版本的 Fabric API、Xaero's World Map、Xaero's Minimap。
- Xaero 底图保留在玩家本地；服务同步区块区域和小镇资料，不汇集成员的地形数据。
- 外置服务仅使用 Node.js 标准库，以原子写入 JSON 保存数据。客户端读取当前游戏玩家实体的 UUID 和名字，小镇权限独立于游戏 OP。
- 领域术语见 [CONTEXT.md](CONTEXT.md)。

## 使用与配置

需要 Node.js 24+、JDK 25+。不需要安装 npm 依赖，也不需要浏览器后台。

```powershell
cd server
node src/server.mjs
```

本地服务默认监听 `127.0.0.1:37841`。需要修改时将 `server/config.example.json` 复制为 `server/config.json`；默认数据文件为 `server/data/yetanothertown.json`。

服务容量配置在启动时校验，超限返回中文提示，不删除已有小镇资料：

| 配置 | 默认值 | 边界 |
| --- | --- | --- |
| `maximumPendingRequests` | 64 | 等待及执行中的业务请求总数 |
| `maximumSessions` / `maximumSessionsPerPlayer` | 10000 / 8 | 总会话与单玩家会话上限；单玩家超限淘汰其最旧会话 |
| `maximumTowns` | 1000 | 新增小镇上限 |
| `maximumTownRecords` | 10000 | 单镇角色、成员、周目、工程、工单总数；已有超限数据仍可读取和修改 |
| `maximumTownBytes` | 7340032（7 MiB） | 小镇数据及响应额外字段的字节预算，为客户端 8 MiB 读取上限留余量；超限数据只允许不增大的编辑 |
| `maximumRateLimitEntries` | 10000 | HTTP 地址及身份尝试限流表的最大键数 |

请求体通过 `maxBodyBytes` 限制，默认 64 KiB；超限流立即拒绝，半包请求受 `requestTimeoutSeconds` 限制。现有全量快照适合小镇规模，扩大小镇总数等配置前应测量响应容量和轮询负载。

安装客户端 JAR 和三个前置模组后，按 **K** 打开小镇界面，按 **M** 打开 Xaero 原生世界地图，按 **X** 查看当前位置工程详情。进入世界后自动使用当前游戏 UUID 连接，无需额外验证。连接后可创建小镇或输入八位数字 ID 加入；密码由管理设置或关闭。玩家可加入多个小镇并切换。新人只读，分配成员权限后即可直接登记工程。

原版“选项 → 控制 → 按键绑定 → Yet Another Town”可修改、清空或重置模组按键，随游戏 `options.txt` 保存；M 使用 Xaero 自身的地图绑定。

可选安装对应版本的 [ModMenu](https://modrinth.com/mod/modmenu)：26.3 用 21.0.0、26.2 用 20.0.3、26.1.2 用 18.0.2。ModMenu 配置入口和小镇主页的“客户端设置”打开同一页面，可修改服务地址、进入工程提示时长与冷却、刷新间隔、动画和工程图层，并跳转原版按键设置。

界面采用原版风格的居中弹窗、石头底纹和按钮。列表支持工程搜索与悬停全文，表单支持滚轮、PageUp／PageDown、Tab 导航及未保存确认。工程创建仅填写名称、类型、简介（`purpose`）和状态，不询问负责人或坐标；区域来自地图右键拖选，负责人由服务端使用当前登录 UUID 决定。

Xaero 大地图悬停工程区块时显示紧凑信息卡：头像在左，右侧为类型物品图标与工程名、玩家游戏 ID，状态跟随名称，简介在头像下方通栏显示。机器用红石粉，建筑用石英，其他用青金石；计划中名称为金色，待修名称为红色。短内容自动收窄，长文字按字体宽度折行；过长简介末尾显示省略号，右键可查看完整详情。头像复用原版皮肤缓存，尚未加载时显示默认头像。

导航到工程后，进入选区任一区块即自动移除导航提示和本模组的临时路标；维修坐标导航在抵达目标 X/Z 方块时结束。平台、目标详情和 Xaero 右键菜单均可停止导航。切换身份、服务、小镇、周目或维度，以及断开连接时清除导航，不删除玩家自己的路标。

主页档案标题右侧显示金色小镇 ID，简介下方紧邻排列石英项目数、红石粉待修项目数（同项目多个工单只计一次）。项目地图、成员权限、小镇世界同排；下方预览最近两项项目，待修优先，再按更新时间倒序。右侧竖排注册、加入和切换入口，与客户端设置等宽。成员审核显示头像和行内“分配权限组”，权限不足或目标为镇长时不显示该操作。权限组常规窗口每页四项，默认图标为泥土、圆石、铁块、绿宝石块。

平台用类型按钮切换全部、建筑、机器、其他，支持搜索；列表简介中的换行与制表符压成空格，详情保留完整内容。项目只从 Xaero 框选创建。详情保留查看地图、编辑项目、导航入口；编辑页包含状态推进、移交负责人、处理工单与删除。删除需确认，由负责人或有工程管理权限的成员执行，原子删除关联工单并释放区块；历史周目禁止删除。存在未保存编辑时先保存或取消，避免切换操作丢失输入。报修只填写内容说明，标题与位置自动生成。

小镇设置在管理页直接编辑，新密码留空保持现状。“展示小镇”默认关闭，由拥有小镇管理权限的管理／镇长切换。加入页列出所有开启展示的小镇，也可在同排输入 ID、密码；公开目录仅返回名称、ID、介绍、图标、服务器、成员数与是否需要密码，不返回成员身份、工程或密码数据。加入仍校验密码，新玩家仍为只读新人。客户端和服务端须一同更新，才能使用展示目录、简化报修和项目删除。

客户端在 Fabric 的 `CLIENT_STARTED` 事件中初始化界面和头像，等待游戏完成 GUI、选项及皮肤管理器的构造，避免启动入口阶段的空指针崩溃。

客户端首次启动生成 `config/yetanothertown.json`：

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `endpoint` | `http://127.0.0.1:37841` | 服务根地址；远程连接使用 HTTPS |
| `entrySubtitleSeconds` | `3` | 进入工程时的 Subtitle 提示时长，0～10 秒；0 关闭 |
| `entryCooldownSeconds` | `8` | 同一工程重复进入提示冷却，1～120 秒；进入其他工程不受影响 |
| `pollIntervalSeconds` | `10` | 当前小镇资料刷新间隔 |
| `animationEnabled` | `true` | 界面装饰动效开关 |
| `projectOverlayEnabled` | `true` | Xaero 原生地图工程高亮图层开关 |
| `mapBindings` | `{}` | 自动缓存的个人 Xaero 实例，仅用于历史地图；历史详情可手动修正 |

配置会校验字段和取值。旧字段、损坏 JSON 或非法取值不会再导致游戏启动崩溃：先将原文件完整备份为同目录的 `yetanothertown.invalid-<随机标识>.json`，再写入全新默认配置，不迁移旧设置。恢复提示保留在客户端配置页，保存设置后消失；服务地址需重新设置；当前地图自动匹配，历史关联可重新指定。若文件读取、备份或保存失败，则保留原文件并禁止后续配置写入，检查文件权限后重启。会话令牌只保留在客户端内存。

服务地址的显式端口须为 1～65535；响应体读取超过 8 MB 时立即中止。服务端只读轮询不再复制全服务数据，仍隔离返回资料；写操作保留原子保存，工程占区在写入事务内再次检查，同镇同周目同维度禁止重叠，包括已完工工程；不同维度或周目独立。

Logo 默认使用 Minecraft 物品 ID，例如 `minecraft:oak_sapling`；也支持资源包贴图 `texture:命名空间:路径.png`。自定义贴图需由成员安装相应资源包。

### 协作功能

| 功能 | 操作与结果 |
| --- | --- |
| 工程 | 在 Xaero 原生 M 地图按右键拖选区块矩形，填写名称、类型、简介和初始状态；计划中可空名，以“预留地块”显示，施工中和已完工必须有具体名称 |
| 地图与进入提示 | 工程使用 Xaero 原生高亮，支持图层显示／隐藏与悬停资料；进入工程以 Subtitle 提示，按 X 打开详情 |
| 维护报修 | 已完工工程可直接报修；只填内容说明，同世界同维度使用当前位置，否则使用工程中心。未解决说明在详情展示，编辑页进入工单处理 |

平台直接展示工程。小镇管理可配置自定义权限组并分配成员；新人固定只读，成员可直接登记，镇长唯一且通过移交变更。负责人维护自己的工程和工单；“管理所有工程”可管理全镇工程并移交负责人。编辑其他成员使用的权限组还需成员管理权限，不能授予超出自身权限的能力。移除成员前须移交其未归档周目的全部工程，包括已完工工程。

创建状态可选计划中、施工中、已完工；后续按“计划中 → 施工中 → 已完工”流转。列表保留全部工程，已完工只隐藏状态文字。报修后自动待维护，最后一张未解决工单完成后恢复完工。创建或调整区域必须通过重叠检查。

功能集中于工程登记、区域介绍与维护报修，不提供留言、聊天、文件、任务板和材料认捐。

当前按全新测试版使用：模组标识为 `yetanothertown`，不迁移旧测试版配置、按键或数据；同名旧客户端配置按上述备份重置流程处理。服务只接受当前 schema 3；测试时使用新的配置与数据文件，并移除游戏 mods 目录中的旧测试版 JAR。

服务加载时校验角色、成员、周目、工程、工单、会话及其关联，损坏文件会保留并拒绝启动。已有工单的工程不能改维度，避免维修位置与工程脱节。服务密码使用异步 scrypt，避免计算密码时阻塞 HTTP 健康检查；写操作仍按事务队列顺序执行。

### 世界与历史

服务器地址、周目世界和维度分别记录。同一地址可以登记多个世界或周目。换周目时新建世界记录，归档旧记录；历史周目只读，保留工程和维护工单。

镇长只需设置一次：进入游戏，打开 M 地图，在“小镇地图设置”点击“使用我所在的地图”；也可在“管理 → 世界与周目 → 详情”将所在地图设为小镇当前世界。普通成员加入后自动跟随当前周目，直接按 M 查看工程、右键框选创建，不再逐人绑定。

自动匹配使用“当前周目 + 游戏服务器地址 + Xaero 地图名称”，工程按维度隔离。主世界、下界、末地和自定义维度默认匹配同名地图；个别维度名称不同，镇长在该维度重复一次设置即可公布专用名称。底图仍由每位玩家自己探索，不上传地形。服务器地址按大小写不敏感匹配，不推测别名、代理地址或同名历史世界；默认地图名称由 Xaero 本地生成，少数玩家名称不同需在 Xaero 恢复一致名称。若同一服务器、同一维度的两个实际世界名称也完全相同，客户端无法区别，须使用不同地图名称。

共享名称匹配且玩家维度、底图加载状态一致时，客户端通过 Xaero 原生接口自动确认玩家实例；必要时将 Single 切为 Manual，已有 Manual、World Spawn 和服务器控制模式不额外切换。未匹配的地图不会自动确认。当前周目不依赖个人绑定缓存，缓存写入失败也不阻止工程图层。历史地图保持只读，保留本机缓存及手动关联入口；主动浏览历史不随刷新切回当前周目。

换周目时由镇长先设定新的当前世界，再归档旧世界。成员刷新后自动跟随；旧快照向先前周目新增工程会被服务端拒绝。旧 alpha11 小镇可继续读取，镇长需做一次上述设置；客户端和外置服务应同时更新。

换周目前保留旧 Xaero 实例，新周目使用独立实例；同镇同维度禁止多个周目共用同一个个人底图。历史查看使用保存的实例并暂停该界面的地图写入，缺少对应底图时明确提示。请同时保留 `config/yetanothertown.json` 和个人 Xaero 地图目录，避免只有业务记录而丢失地形。

## 验证

```powershell
npm run check
npm test
npm run build
```

构建工具下载并核验 Minecraft、Fabric、Xaero、SpongeMixin 和可选 ModMenu 官方依赖，按固定版本分别编译适配层，再合并为 `build/libs/yetanothertown-1.0.0alpha16.jar`。验证包含服务业务与 HTTP 接口测试、客户端配置和地图绑定测试、三个版本的原版按键分发与 Xaero 原生地图右键框选回归，以及静态引用和反射接口检查。仅验证客户端改动可运行 `npm run test:client`。

SpongeMixin `0.15.4+mixin.0.8.7` 仅提供编译期 API；运行时由已有 Fabric Loader 提供，不向 JAR 额外打包依赖。

修改前置适配时运行 `npm run check:compat`：编译单 JAR、核验锁定表中的全部前置混装组合，再运行客户端回归。普通构建只下载基线依赖；额外版本由锁定表的 `alternatives` 指定，校验所用组合写入 `build/compatibility-*.txt`。依赖锁缺失时直接报错，不自动改用线上新版本。

原生地图检查覆盖 Mixin 注入目标、右键选区单位、悬浮提示调用路径和高亮注册；地图覆盖层不使用独立屏幕投影。

## 部署

首版以本地服务验证为目标。单个数据文件只运行一个服务进程。对外部署时将 Node 服务放在 HTTPS 反向代理后，服务端口只对可信网络开放。完整备份服务数据目录及玩家本地 Xaero 地图目录；归档业务记录不会自动备份地形。

## 安全边界

- 服务信任客户端提供的游戏 UUID，不验证其真实性；修改过的客户端可冒用其他 UUID。因此适用于信任成员的小镇协作环境，不能作为公开服务的防冒用认证。不会发送启动器访问令牌或进行 Mojang 会话验证。
- 每次写入均在服务端检查权限、工程状态、周目归档状态和关联关系。
- 小镇加入密码使用带盐哈希保存。
- 全量快照保留容量边界，已有超限历史资料不自动删除或迁移。将 `maximumTowns` 从默认 1000 放大至 10000 时，玩家加入的小镇列表可能超过客户端读取上限；应先做容量评估。本轮没有生产压力测试或在线漏洞库扫描。
- 本工具提供登记与协作，不执行地块保护、物品扣除、机器控制、传送或自动寻路。
- Xaero 前置由玩家从[官方 World Map 页面](https://modrinth.com/mod/xaeros-world-map)和[官方 Minimap 页面](https://modrinth.com/mod/xaeros-minimap)安装，发行包不内置其程序。
