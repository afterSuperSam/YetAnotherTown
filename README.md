# Yet Another Town

基于 Fabric 的 Minecraft 小镇协作模组：在游戏内预留建设区域、登记工程、查看工程范围并提交维护工单。

当前开发代号为 **v1.0.0alpha7**（简称 **v1.0.0a7**）。正式发布必须获得用户明确授权；此前只递增 alpha 序号，不使用正式发布版号或创建正式发布。Fabric 与 npm 元数据使用标准预发布格式 `1.0.0-alpha.7`，JAR 文件使用 `1.0.0alpha7`。

## 架构

- 客户端模组提供“主页 / 平台 / 管理”三个菜单，连接独立小镇服务。
- 一个模组 JAR 包含 Minecraft **26.3、26.2、26.1.2** 的独立适配层。每个游戏版本安装对应版本的 Fabric API、Xaero's World Map、Xaero's Minimap。
- Xaero 底图保留在玩家本地；服务同步区块区域和小镇资料，不汇集成员的地形数据。
- 外置服务仅使用 Node.js 标准库，以原子写入 JSON 保存数据。客户端读取当前游戏玩家实体的 UUID 和名字，小镇权限独立于游戏 OP。
- 领域术语见 [CONTEXT.md](CONTEXT.md)。

截至 2026-10-18，官方最新稳定版为 [Minecraft 26.3](https://www.minecraft.net/en-us/article/minecraft-java-edition-26-3)；从 26.1.2 起的正式版本为下表三版。26.4 快照不在本轮范围内。

已验证的前置组合如下；每个单元格内的版本均可参与组合，必须下载对应 Minecraft 版本的 Fabric 构建。依赖下载地址和校验值固定在 `compat/dependencies.lock.json`。

| 26.3 | 0.19.5 | 0.161.0、0.162.0、0.163.0（均为 +26.3） | 1.46.3、1.46.4、1.47.0 | 26.5.2、26.5.3、26.6.0 |
| 26.2 | 0.19.5 | 0.159.0、0.160.0、0.161.0（均为 +26.2） | 1.46.0、1.46.1、1.47.0 | 26.5.0、26.5.1、26.6.0 |
| 26.1.2 | 0.19.5 | 0.155.0、0.155.2、0.155.3（均为 +26.1.2） | 1.45.0、1.46.0、1.47.0 | 26.4.2、26.5.0、26.6.0 |

每个游戏版本覆盖 3×3×3＝27 组，共 81 组真实依赖字节码与反射接口检查；三套适配层分别编译后放入同一个 JAR。这些检查不启动游戏，不代表每组均经过实机联调。

安装声明最低为 Loader **0.19.3**、Fabric API **0.155.0**、World Map **1.45.0**、Minimap **26.4.2**，同时服从各前置自身的游戏版本和依赖限制。Loader 0.19.3、0.19.4 已解除本模组的安装限制，但本轮官方 Maven 下载超时／TLS 连接失败，尚未取得 JAR 验证；验证基线仍为 0.19.5。安装声明不等于表外版本或未来更新已验证。

## 使用与配置

需要 Node.js 24+、JDK 25+。不需要安装 npm 依赖，也不需要浏览器后台。

```powershell
cd server
node src/server.mjs
```

本地服务默认监听 `127.0.0.1:37841`。需要修改时将 `server/config.example.json` 复制为 `server/config.json`；默认数据文件为 `server/data/yetanothertown.json`。

安装客户端 JAR 和三个前置模组后，按 **K** 打开小镇界面，按 **M** 打开 Xaero 原生世界地图，按 **X** 查看当前位置工程详情。进入世界后自动使用当前游戏 UUID 连接，无需额外验证。连接后可创建小镇或输入八位数字 ID 加入；密码由管理设置或关闭。玩家可加入多个小镇并切换。新人只读，分配成员权限后即可直接登记工程。

原版“选项 → 控制 → 按键绑定 → Yet Another Town”可修改、清空或重置模组按键，随游戏 `options.txt` 保存；M 使用 Xaero 自身的地图绑定。

可选安装对应版本的 [ModMenu](https://modrinth.com/mod/modmenu)：26.3 用 21.0.0、26.2 用 20.0.3、26.1.2 用 18.0.2。ModMenu 配置入口和小镇主页的“客户端设置”打开同一页面，可修改服务地址、进入工程提示时长与冷却、刷新间隔、动画和工程图层，并跳转原版按键设置。

界面采用原版风格的居中弹窗、石头底纹和按钮。列表支持工程搜索与悬停全文，表单支持滚轮、PageUp／PageDown、Tab 导航及未保存确认。工程创建仅填写名称、类型、简介（`purpose`）和状态，不询问负责人或坐标；区域来自地图右键拖选，负责人由服务端使用当前登录 UUID 决定。

主页档案集中显示放大的小镇图标、工程与待修数量、世界与周目；右侧竖排注册、加入和切换入口。成员审核显示原版玩家头像。权限组常规窗口每页四项，可编辑物品图标；新人、成员、管理、镇长默认分别使用泥土、圆石、铁块、绿宝石块，新人与镇长的身份和权限保持固定。小镇设置在管理页直接编辑；新密码留空保持现状，关闭密码使用独立确认按钮。客户端配置标题合并至顶部，原版按键设置与工程图层开关同排。

客户端在 Fabric 的 `CLIENT_STARTED` 事件中初始化界面和头像，等待游戏完成 GUI、选项及皮肤管理器的构造，避免启动入口阶段的空指针崩溃。

客户端首次启动生成 `config/yetanothertown.json`：

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `endpoint` | `http://127.0.0.1:37841` | 服务根地址；远程连接使用 HTTPS |
| `entrySubtitleSeconds` | `3` | 进入工程时的 Subtitle 提示时长，0～10 秒；0 关闭 |
| `entryCooldownSeconds` | `8` | 同一工程重复进入提示冷却，1～120 秒；进入其他工程不受影响 |
| `pollIntervalSeconds` | `10` | 当前小镇资料刷新间隔 |
| `animationEnabled` | `true` | 界面装饰动效开关 |
| `projectOverlayEnabled` | `true` | Xaero 原生地图工程高亮图层开关 |
| `mapBindings` | `{}` | 每个服务、小镇、周目和维度对应的个人 Xaero 地图实例；通过游戏内绑定按钮维护 |

配置会校验字段和取值。会话令牌只保留在客户端内存。

服务地址的显式端口须为 1～65535；响应体读取超过 8 MB 时立即中止。服务端只读轮询不再复制全服务数据，仍隔离返回资料；写操作保留原子保存，工程占区在写入事务内再次检查，同镇同周目同维度禁止重叠，包括已完工工程；不同维度或周目独立。

Logo 默认使用 Minecraft 物品 ID，例如 `minecraft:oak_sapling`；也支持资源包贴图 `texture:命名空间:路径.png`。自定义贴图需由成员安装相应资源包。

### 协作功能

| 功能 | 操作与结果 |
| --- | --- |
| 工程 | 在 Xaero 原生 M 地图按右键拖选区块矩形，填写名称、类型、简介和初始状态；计划中可空名，以“预留地块”显示，施工中和已完工必须有具体名称 |
| 地图与进入提示 | 工程使用 Xaero 原生高亮，支持图层显示／隐藏与悬停资料；进入工程以 Subtitle 提示，按 X 打开详情 |
| 维护报修 | 已完工工程可直接报修；自动关联工程与周目，同世界同维度使用当前位置，否则使用工程中心。工单在工程详情查看与处理 |

平台直接展示工程。小镇管理可配置自定义权限组并分配成员；新人固定只读，成员可直接登记，镇长唯一且通过移交变更。负责人维护自己的工程和工单；“管理所有工程”可管理全镇工程并移交负责人。编辑其他成员使用的权限组还需成员管理权限，不能授予超出自身权限的能力。移除成员前须移交其未归档周目的全部工程，包括已完工工程。

创建状态可选计划中、施工中、已完工；后续按“计划中 → 施工中 → 已完工”流转。列表保留全部工程，已完工只隐藏状态文字。报修后自动待维护，最后一张未解决工单完成后恢复完工。创建或调整区域必须通过重叠检查。

功能集中于工程登记、区域介绍与维护报修，不提供留言、聊天、文件、任务板和材料认捐。

当前按全新测试版使用：模组标识为 `yetanothertown`，配置和默认服务数据采用新文件名，不读取、迁移旧测试版配置、按键或数据。服务只接受当前 schema 3；测试时使用新的配置与数据文件，并移除游戏 mods 目录中的旧测试版 JAR。

### 世界与历史

服务器地址、周目世界和维度分别记录。同一地址可以登记多个世界或周目。换周目时新建世界记录，归档旧记录；历史周目只读，保留工程和维护工单。

首次连接时，仅当服务器地址唯一匹配一个未归档周目，才自动绑定当前个人 Xaero 地图；历史周目不猜测，已有绑定不覆盖。其他情况由成员在“管理 → 世界与周目 → 世界详情”手动绑定；主世界、下界、末地分别绑定。这个操作只保存个人配置，新人和历史记录也可使用，不修改全镇资料。错误绑定可解除后重设。

地图打开失败的提示页和未绑定地图的右键菜单提供“前往绑定当前地图”。多世界身份使用 Xaero 主线程的玩家世界，不依赖后台绘图切换状态；若已绑定底图尚未被 Xaero 确认为玩家所在实例，有创建权限的成员可在当前维度右键选择“确认当前地图为所在世界”，通过 Xaero 原生确认后重新右键创建工程。归档周目保持只读，浏览其他地图不会自动改变玩家所在世界。

换周目前保留旧 Xaero 实例，新周目使用独立实例；同镇同维度禁止多个周目共用同一个个人底图。历史查看使用保存的实例并暂停该界面的地图写入，缺少对应底图时明确提示。请同时保留 `config/yetanothertown.json` 和个人 Xaero 地图目录，避免只有业务记录而丢失地形。

## 验证

```powershell
npm run check
npm test
npm run build
```

构建工具下载并核验 Minecraft、Fabric、Xaero、SpongeMixin 和可选 ModMenu 官方依赖，按固定版本分别编译适配层，再合并为 `build/libs/yetanothertown-1.0.0alpha7.jar`。验证包含服务业务与 HTTP 接口测试、客户端配置和地图绑定测试、三个版本的原版按键分发与 Xaero 原生地图右键框选回归，以及静态引用和反射接口检查。仅验证客户端改动可运行 `npm run test:client`。

SpongeMixin `0.15.4+mixin.0.8.7` 仅提供编译期 API；运行时由已有 Fabric Loader 提供，不向 JAR 额外打包依赖。

修改前置适配时运行 `npm run check:compat`：编译单 JAR、核验锁定表中的全部前置混装组合，再运行客户端回归。普通构建只下载基线依赖；额外版本由锁定表的 `alternatives` 指定，校验所用组合写入 `build/compatibility-*.txt`。依赖锁缺失时直接报错，不自动改用线上新版本。

原生地图检查覆盖 Mixin 注入目标、右键选区单位、悬浮提示调用路径和高亮注册；地图覆盖层不使用独立屏幕投影。

alpha7 本地验证通过：25 项服务测试、183 项客户端断言、三套版本编译和 81 组前置组合静态检查。另有 15 项玩家地图判断回归，以及 9 套真实 Xaero 依赖的 45 项实例解析检查。产物内的模组名称、按键分类、包名与资源路径均已核验。

自动化验证不启动 Minecraft。本轮视觉审查参考用户提供的三张游戏截图；修订后的实机画面、地图框选交互与多人联调仍需在游戏内验收。客户端检查覆盖身份或周目切换后旧请求失效、并发刷新顺序和原版输入分发，服务测试覆盖权限分配、工程维护状态、占区冲突与周目隔离。

## 部署

首版以本地服务验证为目标。单个数据文件只运行一个服务进程。对外部署时将 Node 服务放在 HTTPS 反向代理后，服务端口只对可信网络开放。完整备份服务数据目录及玩家本地 Xaero 地图目录；归档业务记录不会自动备份地形。

## 安全边界

- 服务信任客户端提供的游戏 UUID，不验证其真实性；修改过的客户端可冒用其他 UUID。因此适用于信任成员的小镇协作环境，不能作为公开服务的防冒用认证。不会发送启动器访问令牌或进行 Mojang 会话验证。
- 每次写入均在服务端检查权限、工程状态、周目归档状态和关联关系。
- 小镇加入密码使用带盐哈希保存。
- 本工具提供登记与协作，不执行地块保护、物品扣除、机器控制、传送或自动寻路。
- Xaero 前置由玩家从[官方 World Map 页面](https://modrinth.com/mod/xaeros-world-map)和[官方 Minimap 页面](https://modrinth.com/mod/xaeros-minimap)安装，发行包不内置其程序。
